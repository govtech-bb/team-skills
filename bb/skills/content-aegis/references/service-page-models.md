# Service-page models

Use this reference to decide the content structure before drafting service pages.

Do not select a page model merely because the user asks for it or a pattern exists.

## Contents

- Core rule and diagnosis
- Entry and start models
- Combined and duplicate-entry decisions
- Routing, guidance and what-you-need
- Offline and external services
- Recommendation format and QA

## Core rule

Use:

- entry to help users recognise the service and decide whether they are in the right place
- start to prepare users to begin a transaction
- routing to help users find the correct route
- guidance to explain
- a what-you-need page for long practical preparation
- the form or service to collect information and complete the task

Use the smallest structure that keeps the journey clear, safe and predictable.

Do not optimise for the fewest pages at the expense of user understanding.

## Diagnose the service

Before recommending a model, identify:

1. the user’s main task
2. whether there is a transaction
3. the intended audience
4. the service mode
5. the number of routes
6. whether users must make a decision before starting
7. the amount and type of preparation
8. important eligibility, timing, cost or risk information
9. what happens after the user acts
10. whether supporting explanation is needed outside the transaction

If consequential facts are missing, follow the evidence threshold before drafting.

## Entry point versus entry page

An entry point is wherever someone first encounters the service:

- search result
- directory listing
- homepage link
- related guidance
- direct URL

An entry page is a page intentionally included in the journey.

Do not create an entry page merely because every service needs an entry point.

## Entry page

Job: help users recognise the service, decide whether it is the right place, and move to the correct next step.

Use when:

- users may confuse this service with another
- several related services or routes need orientation
- the journey begins outside GovTech
- the service is offline and needs a clear public entry
- the user must understand a consequential qualifier before continuing
- the page adds meaningful routing or recognition value

Usually include:

- what the service helps with
- who it is for when not obvious
- the route or next destination
- only the timing, eligibility or service-mode detail needed to choose correctly

Do not include:

- full document lists
- long location lists
- detailed process steps
- a second copy of the start page
- a start-style action when the next page contains the real start action

When entry and start are separate, normally use a descriptive navigation link on entry and reserve the transaction button for start.

## Start page

Job: prepare users to begin a transaction.

Use when there is:

- an online form
- an application
- a booking
- a request
- a registration
- another clear transaction

Usually include only confirmed, relevant information:

- what the user can do
- who can use it when needed
- service mode
- critical timing or route blockers
- high-level preparation
- cost and payment
- time to complete
- what happens after submission
- help or alternative access
- the primary transaction action

Do not use a start page when there is no real transaction or next action.

Do not turn it into a full guidance page.

## Combined entry and start page

Job: help users recognise, prepare for and begin one clear transaction from one page.

Use when most of these are true:

- one main task
- one main audience
- one main route
- simple eligibility
- short preparation
- limited exceptions
- no meaningful comparison between services
- critical information stays easy to scan
- a separate entry page would repeat the start page

Do not combine merely because:

- the source is short
- the template allows it
- fewer pages appear simpler
- related services use combined pages

Keep separate when users need:

- meaningful orientation
- route comparison
- structured routing
- risk information before reaching a transaction page
- substantial explanation that would obscure the start action

## Duplicate-entry test

Check for:

`Information page → Register now → Start page → Start now → Form`

Ask:

- does the first page help users choose between services or routes?
- does it add information needed before they reach the start page?
- does its action navigate or falsely feel like the transaction begins?
- would removing or combining it lose anything important?

If it adds no routing or recognition value, recommend removing or combining it.

## Routing page or routing flow

Job: help users find the correct service, route, office, form or next step.

Use when the answer changes:

- eligibility
- service type
- application type
- channel
- office
- form
- next action

Use structured questions or clear route choices.

Do not make users read several rules and diagnose their own route when the service can ask them.

Keep routing questions:

- answerable
- limited to information needed for the route
- free from legal interpretation where possible
- connected to a safe outcome

Do not describe routing as diagnosis, eligibility approval or legal advice unless that is genuinely what the service provides.

## Guidance page

Job: explain supporting information users need before, during or after a service.

Use when users need:

- explanation of a process
- detailed preparation
- special cases
- legal or official terms explained
- steps that happen outside the form
- several locations or responsibilities
- information useful before or after the transaction

Do not create guidance:

- by default
- solely because content is long
- to repeat a start page
- to hold internal background
- when routing should decide the user’s next step
- when a short explanation fits safely on the start page

Guidance must meet a real user need.

Use descriptive task-based titles.

Link guidance from the point where users need it.

## What-you-need page

Job: help users gather practical information or documents before starting.

Use when:

- the preparation list would overwhelm the start page
- users need information from someone else
- several documents require explanation
- preparation takes time
- users may need to leave and return

It is not general guidance.

Usually include:

- documents
- information
- details needed from someone else
- what to do when something is unavailable

Keep a short high-level preview on the start page.

## Offline or external service entry

Use an entry-only page when:

- the service is completed in person, by phone, email or post
- GovTech does not own the transaction
- the next action is visiting, calling, downloading or contacting

State:

- what the user can do
- service mode
- what to prepare
- where or how to continue
- important timing and cost

Use a task-specific link or instruction.

Do not use “Start now” unless a real digital flow begins.

## Guidance versus routing versus preparation

Ask:

1. Does the user need to choose a route?
   - Use routing.
2. Does the user need to collect practical items?
   - Use a what-you-need page when the detail is long.
3. Does the user need explanation?
   - Use guidance.
4. Is the information essential and short?
   - Keep it on start.

Complexity alone does not answer the question.

## Page-model recommendation

For substantial work, use:

```markdown
## Content decision

Recommended approach: [plain-language recommendation]

Why:
- [user or journey reason]
- [user or journey reason]

Journey: [short sequence]
```

Use a confidence label only when it helps the user understand evidence risk.

If used:

- High: the sources support the model
- Medium: the model is likely but some facts need confirmation
- Low: provide structure only and explain the blocking gap

Do not give a low-confidence final-looking draft.

## Decision sequence

Use this order:

1. Is there a real transaction?
2. Do users need orientation before it?
3. Do users need to choose a route?
4. Can recognition and preparation stay clear on one page?
5. Is practical preparation too long for start?
6. Is explanation needed outside the transaction?
7. Is the next action online, offline or external?

## Model QA

Before drafting, check:

- each proposed page has one distinct job
- no page exists only because of a template
- no duplicate start-style action appears before the form
- route decisions are not pushed into prose
- critical information remains visible early
- guidance is not a dumping ground
- preparation is not mistaken for explanation
- the model reflects the actual service mode
- the proposed journey includes completion and next steps
